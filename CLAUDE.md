# FlashFiller — working notes for Claude sessions

Personal Chrome MV3 job-application autofill extension. Spec: README.MD.

## Build / test (no system Node!)

```bash
export PATH="$HOME/.local/node-dist/node-v24.18.0-darwin-arm64/bin:$PATH"
npx vitest run        # full suite (590 tests as of 2026-07-17)
npm run build         # tsc + vite → dist/   (never "npm build")
```

- Load unpacked from `dist/` (never the repo root). After every rebuild: refresh at chrome://extensions **and reload the target tab** — stale content scripts survive extension reloads.
- Never run `npm run dev` and walk away — it leaves dist/ in dev-server mode that breaks when the server stops.

## Architecture (src/)

- `content/detector.ts` — reads the DOM, never writes (except `data-ff-id` stamps). Label resolution (placeholder-aware), radio/checkbox/date-segment grouping, repeated-section indexing (`sectionIndex`/`sectionKind`), site-chrome exclusion.
- `content/matcher.ts` — pure, no DOM. Tier 1: pattern → profile getters (scoped: distinctive stems match sentences, ambiguous words only short labels). Tier 2: scored qa/seed matching. `chooseOption(s)` places answers on options (intent-aware polarity veto).
- `content/autofill.ts` — the ONLY module that writes to the DOM. Native setters + real events; segmented-date keystroke typing; custom dropdowns: open → poll options → pointer-sequence click → display-text verification → keyboard (ArrowDown/Enter) fallback → honest 'failed'.
- `content/index.ts` — bootstrap: scan → match → fill loop, session answers, capture loop, chips, `[FlashFiller]` console breadcrumbs, post-fill validation run.
- `content/validate.ts` — validation layer (reads, NEVER writes): after autofill settles, compares every field's actual page state vs the expected answer (tolerant: date formats, state/country variants, polarity). Verdicts ok/wrong/missing-answerable/missing-unanswered drive fix chips + `[FlashFiller] validation` console lines + `window.__flashfillerValidate()`. The filler is never its own validator.
- `lib/` — dates (canonical "YYYY-MM"), storage (chrome.storage + migrations, schema v5), schema (zod), seed catalog loader, judge-text parsing, documents (`lib/documents.ts`: resume/cover-letter store under its OWN key `flashfiller_documents_v1` — base64 payloads never ride through the zod-parsed main store; pure `pickDocument` matching brain). `public/seed-questions.json` = 114-question seed bank; `flashfiller-profile-import.local.json` carries 58 pre-answered entries (source docs/AdditionalQuestions.MD).
- `background/service-worker.ts` — badge, trusted-input CDP tiers, and the OPT-IN OpenAI semantic judge (drift matching / option inference / free-text drafting; gated on Settings → Semantic matching + API key; no key = zero network).

## House rules

- LEARNED-ANSWER GATE (2026-07-16 rebuild, user-confirmed — SUPERSEDES the 2026-07-14 full-autonomy note): full autonomy stands for profile/tier-1 matches, curated entries (source training/import), seeds, and in-session judge fills. LEARNED entries (source captured/inferred) are gated: they save as needs_review (suggest-only) until approved in the Review tab or via a suggestion-chip Accept (accept = approve). Even approved, they autofill only on exact/near-exact question wording (`CAPTURED_AUTOFILL_MIN` 0.95 on the pre-clamp question score) or an embedding-semantic match with margin — until they GRADUATE (okCount ≥ 3 validated fills, no wrongs → normal thresholds). Validation `wrong` on a learned fill: first = recorded strike, second = auto-demote back to Review with evidence; curated entries never auto-demote. Capture hygiene (`prepareCaptureValue`): junk question keys (name/id-derived) skip, dates canonicalize to ISO (ambiguous DD/MM resolves against profile dates or skips), placeholder noise skips, page-branded answers get `siteScope`-pinned. Consent boxes with stored curated answers still auto-fill; judge is still called when nothing stored matches. Hard limits unchanged: EEO and consent are never INFERRED (stored answers only), file uploads attach ONLY user-stored documents (2026-07-17 supersession — see DOCUMENT UPLOADS below), notify entries chip, judge declines (UNKNOWN/0) → honest failure chip, and never auto-submit.
- SEMANTIC LAYER (Phase 2, same 2026-07-16 rebuild): embeddings (text-embedding-3-small, 256d) behind the SAME opt-in gate as the judge — no key = zero network, lexical-only. Vectors cache locally (`lib/embed-cache.ts`, `flashfiller_embed_cache_v1`). Uses: question paraphrase detection with margin + qualifier guard (`conflictingQualifiers` — "current" vs "desired" salary never bridges, whatever the cosine), and option placement (`semanticChooseOption` tier 1). Validated semantic bridges DISTILL: drift → aliases, option picks → auto option-equivalence sets (`recordOptionEquivalence`) — the system converges toward offline.
- POISONED-ALIAS DEFENSES (2026-07-16 night, live corruption: "School or University*" aliased onto a captured disability answer): SPA node recycling can misattribute captured values across widgets, so (1) the dropdown-diff capture tracks question identity per data-ff-id and skips on identity change; (2) capture merges and drift aliasing never bridge EEO ↔ non-EEO wordings (`lib/eeo.ts` crossesEeoTopic — also the detector's EEO_RE source, now incl. hispanic/latino); (3) matcher skips learned candidates whose primary question crosses the EEO line vs the field; (4) ungraduated learned entries matching only via an alias (primary question unrelated to the field) SUGGEST, never autofill; (5) score ties prefer curated over learned; (6) opaque hex/uuid values never capture; (7) migration v6→v7 scrubs all of the above from existing stores.
- DOCUMENT UPLOADS (2026-07-17, user-directed resume feature — SUPERSEDES the old "file uploads untouched" hard limit): documents the user stores in Options → Documents auto-attach to matching file inputs (File + DataTransfer → `input.files` + events; synthetic dragenter/dragover/drop on the upload zone as fallback; honest `failed` chip after both). `pickDocument` is honest — cue-typed zones only ever get their own kind (cover-letter zone with no stored cover letter = flag chip, never the resume), `accept` is respected, persona-pinned docs stay pinned. `settings.autoAttachDocuments` OFF = suggest-only chips. Documents attach FIRST in the fill order (Workday resume-parser overwrite mitigation). Still forbidden: capturing/storing files FROM pages, attaching more than the one picked document, generated cover letters (out of scope v1). Validation verifies the file was HANDED to the page (input.files / zone filename chip), not that the site's server upload succeeded.
- Never auto-submit anything.
- Debugging live-site widgets: ask the user for the widget's `outerHTML` (closed + opened popup) and the `[FlashFiller]` console lines — this has solved every Workday widget so far (see date.md for the pattern).
- Update `docs/testing-checklist.md` when shipping widget-affecting changes; update ROADMAP.md when scope changes.
